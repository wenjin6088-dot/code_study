## 작업 요약
실제 Chrome 브라우저로 회원가입(`/register`) 페이지에 접속해서, 새 이메일/비밀번호로 가입을 진행했을 때 실제로 계정이 만들어지고 다음 화면(로그인 페이지)으로 잘 넘어가는지 눈으로 직접 확인했습니다. 이건 자동화된 테스트(pytest, vitest)와는 별개로, "진짜 사람이 브라우저에서 썼을 때도 똑같이 동작하는가"를 검증하는 단계입니다.

진행한 절차:
1. 백엔드(FastAPI, 8000번 포트)와 프론트엔드(Vite, 5173번 포트) 개발 서버를 함께 실행
2. `http://localhost:5173/register` 접속
3. Email에 `testuser01@example.com`, Password/Confirm Password에 `Password123` 입력 후 "Register" 버튼 클릭
4. 결과: 회원가입이 성공적으로 처리되었고, 화면이 자동으로 `/login` 페이지로 전환됨

이는 설계된 동작과 일치합니다. 회원가입 API는 가입만 처리할 뿐 로그인 쿠키를 발급하지 않기 때문에(T035 설계), 가입 직후 사용자를 바로 로그인 상태로 만들지 않고 로그인 페이지로 안내하는 것이 올바른 흐름입니다.
