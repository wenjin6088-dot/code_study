# TASK-059. 프로젝트 제목 수정 브라우저 수동 테스트

## 상태
완료 (UI 한계 있음, 비고 참고)

## 날짜
2026-11-09

## 작업 요약
프로젝트 제목을 수정했을 때 변경사항이 실제로 저장되고, 페이지를 새로고침해도 유지되는지(= 서버에 영속화되는지) 확인하는 작업입니다.

T051-T056(Phase 4 프론트엔드 범위)에는 "제목 수정 UI"가 별도 작업으로 포함되어 있지 않아, 현재 화면에는 제목을 바로 고칠 수 있는 버튼/폼이 없습니다. 그래서 이번 테스트는 백엔드 API(`PATCH /api/v1/projects/{id}`, T049에서 이미 구현·테스트 완료)를 브라우저의 `fetch`로 직접 호출해서 "수정 기능 자체(백엔드)가 정상 동작하고, 화면이 그 결과를 올바르게 반영하는지"를 검증했습니다.

절차:
1. 로그인된 브라우저 세션에서 `fetch(PATCH /projects/{id}, {title: "파이썬 기초 학습 (수정됨)"})` 호출 → 200 응답과 수정된 제목을 담은 본문 확인
2. 같은 상세 페이지를 새로고침 → 화면에 "파이썬 기초 학습 (수정됨)"으로 정상 반영되어 표시됨

## 비고
**UI 공백 발견**: 현재 Dashboard/ProjectCard/ProjectDetail 어디에도 "제목 수정" 버튼이나 입력 폼이 없습니다. tasks.md의 Frontend: Project UI 섹션(T051-T056)에 수정 UI가 명시적으로 포함되지 않았기 때문입니다. 백엔드 PATCH 엔드포인트는 완성되어 있으니, 실제 "수정" 사용자 흐름이 필요하면 별도 작업(예: ProjectDetail에 인라인 편집 또는 "Edit" 버튼 + 모달 추가)으로 백로그에 등록하는 것을 제안합니다. T042(로그아웃 버튼 UI 부재)와 같은 종류의 공백입니다.

## 재검증 (2026-11-10, Playwright MCP)
동일한 UI 공백이 여전히 존재함을 재확인(ProjectDetail.tsx에 edit 버튼/폼 없음, 프론트엔드 전체에서 `updateProject()` 호출하는 컴포넌트 없음 — grep으로 확인). 이전과 같은 방식으로 인증된 브라우저 세션에서 `fetch()`로 백엔드 PATCH를 직접 호출해 검증했습니다.

절차 및 결과:
1. `fetch('http://localhost:8000/api/v1/projects/{id}', {method:'PATCH', credentials:'include', body:{title:'Playwright 테스트 프로젝트 (수정됨)'}})` → 200, 응답 본문에 변경된 제목 확인
2. 상세 페이지(`/projects/{id}`) 새로고침 → 화면에 "Playwright 테스트 프로젝트 (수정됨)"으로 정상 반영

UI 공백은 이전 보고서와 동일하게 유효하며 추가로 발견된 사항 없음.

## 재검증 (2026-11-12, Playwright MCP) — UI 공백 해소 확인
T056a("Edit" 버튼/폼 추가)가 완료되어, 이번에는 **fetch 우회 없이 실제 UI 흐름**으로 재검증했습니다.

절차:
1. 상세 페이지에서 "Edit" 버튼 클릭(일반 `browser_click`은 반응 없음 — T057 재검증과 동일한 trusted-click 미반응 현상 재현, `page.evaluate`로 JS `.click()` 우회) → Title/Description 입력 폼으로 전환, 기존 값이 올바르게 프리필됨 확인
2. Title을 "Playwright 재검증 프로젝트 T57-60 (수정됨)"으로 변경 후 "Save" 버튼 클릭(동일하게 JS `.click()` 우회) → 폼이 닫히고 화면에 즉시 새 제목 반영
3. 페이지 전체 새로고침(`browser_navigate`로 동일 URL 재방문, 클라이언트 캐시가 아닌 서버 재조회 유도) → 새로고침 후에도 "Playwright 재검증 프로젝트 T57-60 (수정됨)"으로 유지됨 — PATCH 결과가 서버에 정상 영속화됨을 UI 레벨에서 재확인

**결론**: 이전 보고서에서 지적한 "제목 수정 UI 없음" 공백은 T056a로 해소되었고, 실제 Edit 버튼→폼→Save 흐름이 정상 동작함을 확인했습니다.
