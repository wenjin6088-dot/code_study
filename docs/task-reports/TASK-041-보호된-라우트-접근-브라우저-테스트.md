# TASK-041. 비로그인 상태의 보호된 라우트 접근 브라우저 테스트

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
로그인하지 않은 상태(또는 로그아웃한 상태)에서 보호된 페이지인 `/trash`에 직접 주소를 입력해 접근했을 때, `ProtectedRoute` 컴포넌트가 의도대로 `/login` 페이지로 돌려보내는지 확인했습니다.

처음 테스트했을 때는 리다이렉트가 되지 않고 `/trash` 내용이 그대로 보이는 문제가 있었습니다. 원인을 추적해보니 앱 코드의 문제가 아니라, TASK-042에서 발견한 "로그아웃 API가 쿠키를 지우지 않는" 버그 때문에 실제로는 로그아웃이 되지 않은 상태(여전히 유효한 `access_token` 쿠키 보유)였던 것이었습니다. 해당 버그를 수정(TASK-042 참고)한 뒤 다시 테스트하니:

1. 로그아웃 API(쿠키 삭제가 반영된 버전)를 호출해 완전히 비로그인 상태로 만듦 (`GET /auth/me`가 401 반환하는 것으로 확인)
2. `/trash` 주소로 직접 이동
3. 결과: 즉시 `/login` 페이지로 리다이렉트됨 (주소창이 `http://localhost:5173/login`으로 바뀜)

`ProtectedRoute`(frontend/src/components/auth/ProtectedRoute.tsx)와 `useAuth`(frontend/src/hooks/useAuth.ts)가 설계대로 동작함을 확인했습니다: 인증 상태를 서버에 물어보고(`GET /auth/me`), 실패하면 로그인 페이지로 돌려보냅니다.
