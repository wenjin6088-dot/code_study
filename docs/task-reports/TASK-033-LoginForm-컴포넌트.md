완료

## 작업 요약
로그인 화면용 입력 폼을 `frontend/src/components/auth/LoginForm.tsx`에 만들었습니다. 구조는 RegisterForm(T032)과 거의 같지만 필드가 이메일/비밀번호 2개뿐이고, 버튼 문구가 "Login"입니다. 유효성 검사는 이메일 형식 확인과 비밀번호가 비어있는지 확인, 두 가지만 합니다(회원가입과 달리 비밀번호 길이나 확인 값은 로그인 단계에서 검사할 이유가 없습니다 — 어차피 서버가 맞는지 틀린지 판단합니다).

검사를 통과하면 T034의 `authService.login(email, password)`을 호출하고, 요청 중에는 버튼을 비활성화합니다. 성공하면 `onSuccess` prop으로 로그인한 사용자를 넘기고, 실패하면("이메일 또는 비밀번호가 올바르지 않습니다") 그 메시지를 화면에 보여주고 다시 시도할 수 있게 합니다.

## 기술 결정
- **RegisterForm과 같은 패턴 재사용, 공통 컴포넌트로 추출하지 않음**: 두 폼이 구조적으로 비슷하지만 필드 개수와 검사 규칙이 다릅니다. 지금 시점에 억지로 공통 `AuthForm`을 만들면 오히려 분기(필드 유무, 검사 규칙)가 복잡해져서, 테스트가 요구하지 않는 추상화를 추가하지 않는 것이 YAGNI 원칙에 맞다고 판단했습니다.
- **비밀번호 빈 값 검사만 수행, 길이 제한 없음**: 테스트는 "비밀번호가 비어있으면 `required`류 메시지"만 요구합니다. 길이 검사를 넣으면 테스트에 없는 동작을 추가하는 것이라 생략했습니다.
- **버튼은 `frontend/src/components/ui/button.tsx`의 `Button` 재사용**: 프로젝트에 이미 있는 shadcn 스타일 버튼을 그대로 썼습니다.
