# TASK-020. axios API 클라이언트 설정

## 상태
완료

## 날짜

## 작업 요약
프론트엔드 곳곳에서 백엔드를 호출할 때마다 매번 "주소를 어디로 할지", "쿠키를 같이 보낼지", "에러가 나면 어떤 모양으로 받을지"를 새로 정하면 코드가 제각각이 됩니다. `api-client.ts`는 이런 공통 설정을 한 곳에 모아두는 "표준 전화기"입니다 — 앞으로 모든 API 호출은 이 전화기를 통해서만 이루어집니다.

`frontend/src/services/api-client.ts`에 axios 인스턴스를 만들었습니다.

1. **`baseURL`**: `VITE_API_BASE_URL` 환경변수가 있으면 그 값을, 없으면 quickstart.md에 안내된 기본값(`http://localhost:8000/api/v1`)을 씁니다. 덕분에 환경변수 설정 없이도 로컬 개발이 바로 됩니다.
2. **`withCredentials: true`**: research.md에서 정한 "HTTPOnly 쿠키 기반 JWT 인증" 방식을 쓰려면, 브라우저가 쿠키를 요청에 자동으로 실어 보내야 합니다. 이 옵션이 없으면 로그인 후에도 매 요청에 인증 쿠키가 빠져서 로그인이 안 된 것처럼 동작합니다.
3. **응답 인터셉터(에러 변환기)**: T016에서 백엔드가 모든 에러를 `{"error": {"message": "..."}}` 형식으로 통일했는데, 이 인터셉터가 그 형식을 꺼내서 평범한 `Error` 객체로 바꿔줍니다. 그러면 프론트엔드 코드는 어떤 API를 호출하든 항상 `catch (e) { e.message }`로만 에러 문구를 꺼내면 됩니다.

## TDD 결과
- axios 설정 자체는 비즈니스 로직이 아니지만, "실제로 백엔드와 통신하고, 에러 형식이 올바르게 변환되는가"는 반드시 실제로 확인이 필요해서 Playwright로 실제 브라우저에서 검증했습니다 (이번엔 소스 코드에 임시 테스트 파일/라우트를 만들지 않고, 브라우저에서 `import('/src/services/api-client.ts')`로 모듈을 직접 불러와 테스트했습니다 — 더 가볍고 흔적이 안 남는 방식).
  - `eslint`, `prettier --check` 통과
  - `npm run build`(타입체크 + 프로덕션 빌드) 성공 — `import.meta.env.VITE_API_BASE_URL` 접근이 Vite의 기본 타입 정의로도 타입 에러 없이 통과함을 확인
  - 백엔드(`uvicorn`)와 프론트엔드(`vite`) 서버를 모두 실행한 뒤, 실제 브라우저(Playwright)에서:
    - `apiClient.defaults.baseURL` → `http://localhost:8000/api/v1` (기본값 정상 적용)
    - `apiClient.defaults.withCredentials` → `true`
    - 존재하지 않는 경로(`/nonexistent`)로 `GET` 요청 → 백엔드가 `{"error":{"message":"Not Found"}}`로 응답 → 인터셉터를 거쳐 **`Error` 인스턴스, `message: "Not Found"`**로 정확히 변환됨을 확인. 이 과정에서 CORS가 실제로 막히지 않고 정상적으로 요청-응답이 오갔다는 것도 함께 증명됨(CORS가 막혔다면 응답 데이터 없는 네트워크 에러가 났을 것).
  - **중간에 발견한 환경 이슈**: 이전 검증(T018/T019)에서 백그라운드로 띄운 `npm run dev` 프로세스가 완전히 종료되지 않고 포트 5173/5174를 계속 점유하고 있었습니다. `Get-NetTCPConnection`으로 점유 프로세스(PID)를 찾아 강제 종료한 뒤 재시도해 해결했습니다.
  - 검증 후 모든 서버 프로세스와 Playwright가 남긴 스냅샷/로그 파일을 정리했습니다.
- 저장소가 아직 git으로 초기화되지 않아 관련 커밋은 생성하지 않았습니다.
- 테스트 커버리지: 해당 없음 (클라이언트 설정, 아직 이 클라이언트를 사용하는 서비스 코드 없음)

## 기술 결정
- **`VITE_API_BASE_URL` 환경변수 + fallback 기본값**: quickstart.md가 `frontend/.env.local`에 이 변수를 두도록 안내하고 있지만, 현재 tasks.md에는 이 파일을 만드는 Task가 명시적으로 없어서 실제 `.env.local` 파일은 만들지 않았습니다(범위 외 작업 방지). 대신 세션 내 다른 환경변수들(`DATABASE_URL` 등)과 같은 패턴으로, 값이 없을 때 quickstart.md의 기본값으로 동작하도록 했습니다.
- **에러 응답 인터셉터로 백엔드 에러 스키마와 1:1 연동**: T016에서 만든 `{"error": {"message": ...}}` 형식을 프론트엔드가 알아서 풀어주지 않으면, 모든 API 호출 지점에서 `error.response.data.error.message`라는 긴 경로를 반복해서 써야 합니다. 이 인터셉터 하나로 그 반복을 없앴습니다.
- **`axios` 인스턴스를 그대로 export (별도 wrapper 함수 없음)**: GET/POST 등을 감싸는 커스텀 헬퍼 함수를 추가로 만들지 않았습니다. axios 인스턴스 자체가 이미 `.get()`, `.post()` 등을 제공하고, 실제 호출 패턴(쿼리 파라미터, FormData 업로드 등)은 각 서비스 Task(T034 인증 서비스, T053 프로젝트 서비스, T069 코드 업로드 등)에서 구체화되는 게 맞다고 판단해 지금은 최소한으로 유지했습니다(YAGNI).
- **401(인증 만료) 자동 처리 미구현**: 액세스 토큰 만료 시 자동으로 리프레시하는 로직은 T038("자동 토큰 갱신 로직")이 명시적으로 담당하는 영역이라, 이번 Task에서는 건드리지 않았습니다.
