## 작업 요약
`/login` 페이지에서 TASK-039에서 가입한 계정으로 실제 로그인을 시도하고, 성공 시 대시보드(`/`)로 잘 이동하는지 확인했습니다.

진행한 절차와 발견한 문제:
1. 처음 시도했을 때 백엔드가 500/503 오류를 반환했습니다. 원인은 `uvicorn` 개발 서버를 `.env` 파일을 읽지 않은 채로 직접 실행해서 `JWT_SECRET_KEY` 환경변수가 비어있었기 때문입니다 (코드 버그가 아니라 서버 실행 방식 문제). `uvicorn ... --env-file ../.env` 옵션으로 서버를 다시 실행해서 해결했습니다.
2. 환경변수 문제를 해결한 뒤 다시 로그인을 시도하니, `testuser01@example.com` / `Password123`으로 로그인에 성공했고 화면이 자동으로 대시보드(`/`)로 이동했습니다.
3. 대시보드로 이동한 직후 `ProtectedRoute`가 내부적으로 `GET /auth/me`를 호출해 로그인 상태를 재확인하는 것도 네트워크 로그로 확인했습니다 (정상 200 응답).

테스트 중 사소하게, 브라우저 자동화 도구(Claude in Chrome)의 좌표 클릭이 가끔 폼 제출 이벤트를 못 일으키는 경우가 있었는데, 이는 테스트 도구 자체의 특성이며 실제 사람이 마우스로 클릭할 때는 발생하지 않는 문제입니다 (JS로 `form.requestSubmit()`을 호출해 재확인, 정상 동작 확인).
