## 상태
완료

## 날짜
2026-11-19

## 작업 요약
실습 문제(연습 문제) 하나하나를 데이터베이스에 저장하기 위한 `PracticeProblem` 모델을 만들었습니다. 쉽게 말하면, 학습 문서가 "교과서"라면 실습 문제는 "문제집"에 해당합니다. 각 Task(작업)마다 5개의 문제가 생기는데, 이 모델은 그 문제 1개 1개의 생김새(어떤 정보를 담는지)를 정의합니다.

담고 있는 정보는: 문제 번호(1~5), 문제 유형(따라하기/빈칸채우기/수정하기/디버깅/새로만들기), 문제 지문, 학습 목표, 힌트 목록(여러 개를 순서대로 공개하는 배열), 모범 답안, 예상 출력 결과입니다. 이 테이블은 이미 2025-11-15에 만들어진 초기 DB 마이그레이션(T009)에 `practice_problems`라는 이름으로 설계되어 있었는데, 지금까지는 이 테이블을 다루는 Python 코드(ORM 모델)가 없었습니다. 이번에 그 빈 자리를 채웠습니다.

## 변경 파일
- `backend/src/models/practice_problem.py` (신규)

## TDD 결과
모델 자체에는 별도 단위 테스트를 작성하지 않았습니다. 이 프로젝트의 기존 관례(예: `LearningDocument` 모델)와 동일하게, 모델은 그 자체로는 테스트하지 않고 이 모델을 사용하는 서비스/태스크 계층의 통합 테스트(T117/T118/T120, 실제 PostgreSQL 연결)를 통해 간접적으로 검증했습니다.
- 커밋: 아직 생성하지 않음 (git 저장소는 이번 세션에 새로 초기화했으며, 사용자 요청 시 커밋을 생성할 예정)
- 테스트 커버리지: 해당 모델이 쓰이는 통합 테스트 전체 통과 (backend 413개 테스트 전체 통과)

## 기술 결정
마이그레이션에 이미 정해진 컬럼/제약조건(문제 번호 1~5, 문제 유형 5종 CHECK 제약, task당 번호 unique)을 그대로 따랐고, 기존 `LearningDocument` 모델과 동일한 코드 스타일(SQLAlchemy 2.0 `Mapped`/`mapped_column`)을 사용해 일관성을 유지했습니다.
