# TASK-118. Celery 실습 문제 생성 비동기 태스크 구현

## 상태
완료

## 날짜
2026-11-19

## 작업 요약
실습 문제 생성은 AI 응답을 몇 초~몇십 초 기다려야 하는 무거운 작업이라, 사용자를 기다리게 하지 않고 백그라운드(Celery 워커)에서 처리하도록 만들었습니다. 문서 생성 태스크(T094)와 같은 설계 패턴을 따랐습니다: "진짜 로직"(`generate_practice_async`)과 "Celery가 실행하는 얇은 껍데기"(`generate_practice_task`)를 분리했습니다. 이렇게 나누면 Celery 워커나 실제 Gemini API 키 없이도 핵심 로직을 테스트할 수 있습니다.

다만 학습 문서와 달리 `practice_problems` 테이블에는 "생성 중/완료/실패" 같은 상태 컬럼이 없습니다(데이터 모델에 원래 그렇게 설계됨). 그래서 이 태스크는 성공하면 문제 5개를 한꺼번에 저장하고, 실패하면 아무것도 저장하지 않고 로그만 남깁니다(에러를 터뜨려서 Celery 재시도 루프에 빠지지 않도록). 또한 이미 문제가 존재하는 Task에 대해서는 다시 생성하지 않도록(중복 방지) 만들었습니다.

## 기술 결정
실패를 기록할 상태 컬럼이 없다는 제약을 "일단 상태 컬럼을 DB에 추가하자"로 풀지 않고, 현재 스키마 안에서 가장 단순하게 풀었습니다(성공 시 전부 저장/실패 시 전부 생략 + 로그). 데이터 모델을 바꾸는 건 이번 Phase 7 작업 범위를 벗어나는 결정이라 판단했습니다(YAGNI).
