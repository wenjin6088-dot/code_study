## 작업 요약
`backend/src/services/ai/prompts.py`에 7챕터 학습 문서 생성을 위한 프롬프트 템플릿을 구현했습니다. T093 `DocumentGenerationService`가 `build_document_prompt(...)` 한 번으로 system instruction과 user prompt를 받아 T091 `GeminiClient.generate_json()`에 그대로 넘길 수 있도록 설계했습니다.

- **`DOCUMENT_SYSTEM_INSTRUCTION`**: research.md의 역할 지시("expert teacher ... complete beginners with zero programming knowledge") + 전문용어는 반드시 일상 언어와 비유로 먼저 소개 + JSON 객체만 응답.
- **`CHAPTER_KEYS`**: `("chapter1", ..., "chapter7")` — T090 `learning_documents.valid_content_structure` CHECK 제약과 동일한 키 집합. T093의 응답 검증에서 재사용.
- **`CodeFileInput(path, content)` / `format_code_files()`**: 파일별로 `### 경로` 헤더 + 확장자 기반 언어 펜스 + `N: ` 줄 번호 접두. 줄 번호는 Ch4 line-by-line의 `line_start/line_end` 정확도와 프론트엔드 동기 스크롤(T112)의 기준이 됨.
- **`build_document_prompt(files, detected_language, complexity_level, output_language="Korean") -> PromptBundle`**: 컨텍스트(언어·복잡도·출력 언어) + 번호 매긴 소스 + 챕터별 규칙 + data-model.md 기반 JSON 스키마 예시를 조합. 비어 있는 파일만 주어지면 `ValueError`.
- **챕터 규칙(FR-027~034 반영)**: Ch1 한 문장·무전문용어, Ch2 개념 최대 5개(name/explanation/analogy/example/use_cases), Ch3 Mermaid 플로차트 + 파일별 breakdown, Ch4 항목마다 what_it_does/syntax_breakdown/analogy/alternative_example/notes + file/line_start/line_end, Ch5 단계별 데이터 상태, Ch6 what_it_is/why_used/where_applied, Ch7 실수 3~5개(wrong/right/why/fix).

단위 테스트 19개(`tests/unit/test_prompts.py`)에 더해, 실제 Gemini로 9줄짜리 파이썬 코드에 대해 문서를 1회 생성해 구조 검증 13개 항목(7키 순서, 챕터별 필수 필드, Ch2 ≤5, Ch7 3~5, Ch4 줄 번호 범위, 한국어 출력)을 **13/13 통과**, 생성 시간 18.7초(FR-083 기준 180초)였습니다.

## 기술 결정
1. **스키마를 "예시 JSON + 규칙 텍스트"로 전달, SDK의 response_schema는 미사용**: data-model.md의 구조가 챕터마다 모양이 달라(객체/배열/맵 혼재) 선언적 스키마로 옮기면 템플릿 가독성이 크게 떨어짐. JSON 모드(T091) + 예시 구조만으로 실제 생성에서 키 순서까지 정확히 재현됨을 확인했으므로 단순한 쪽을 택함. 응답 구조 검증은 T093에서 `CHAPTER_KEYS` 기준으로 수행.
2. **Ch4 항목에 `file`/`line_start`/`line_end` 추가**: data-model.md는 `explanations: [...]`로만 정의되어 있어 항목 형태는 이 태스크에서 확정. FR-031 다섯 필드에 더해 위치 정보를 넣어 프론트엔드 코드 패널-설명 패널 동기 스크롤(T105/T112)이 가능하게 함. 이를 위해 소스에 줄 번호를 접두하고, 프롬프트에 "접두 번호는 코드가 아님"을 명시.
3. **출력 언어 기본값 한국어**: spec 가정 6("educational content ... in Korean, 코드 설명은 영어 가능"). `output_language` 인자로 변경 가능하게 열어 두되 기본은 Korean. 코드·식별자·JSON 키는 원문 유지하도록 지시.
4. **Ch3 플로차트는 Mermaid로 고정**: data-model.md는 "ASCII/Mermaid"를 허용하나 프론트엔드 렌더링 일관성을 위해 Mermaid 하나로 통일.
5. **프롬프트 상수(최대 개념 5, 실수 3~5)를 모듈 상수로 노출**: T093 검증과 테스트가 같은 값을 참조하도록 함.
