## 기술 결정 — 발견한 버그와 수정
**발견한 버그**: Task 1의 문서 생성은 성공했는데, 곧바로 자동 트리거된 실습 문제 생성이 워커 로그에서 `AttributeError: 'NoneType' object has no attribute 'send'`로 실패했습니다.

**원인**: `document_generation.py`와 `practice_generation.py`의 Celery 태스크는 각각 `asyncio.run(_run(...))`으로 자신만의 새 이벤트 루프를 만듭니다. 그런데 DB 연결 풀(`engine`, `src/db/session.py`)은 모듈을 처음 import할 때 딱 한 번만 만들어지는 전역 객체라서, 같은 워커 프로세스 안에서 "문서 생성 태스크"가 끝난 뒤 "실습 문제 생성 태스크"가 실행되면 — 이전 태스크의 이벤트 루프에 묶여 있던 커넥션을 새 이벤트 루프에서 재사용하려다가 Windows의 asyncio Proactor 구현이 깨지는 것이었습니다. 두 태스크가 한 워커 프로세스에서 연속으로 실행될 때만 재현되는 문제라, 자동화 테스트(각 테스트가 서비스 계층을 가짜(fake)로 직접 호출)로는 전혀 잡히지 않았습니다.

**수정**: 각 Celery 태스크의 `_run()` 함수가 작업을 마친 뒤 `await engine.dispose()`를 호출해 연결 풀을 비우도록 했습니다. 그러면 다음 `asyncio.run()`이 새 이벤트 루프로 완전히 새 연결을 맺습니다. 수정 후 워커를 재시작해 Task 2(곱하기 함수)로 다시 테스트하니 문서 생성(17초) → 실습 문제 생성(11초)이 연속으로 정상 성공했습니다.

## 비고
이 버그는 문서 생성만 단독으로 쓰던 지금까지는 드러나지 않았고, "문서 생성 → 실습 문제 생성"이 같은 프로세스에서 연쇄적으로 실행되는 이번 Phase 7의 T119 트리거 때문에 처음으로 실제 환경에서 나타났습니다. 실제 운영 환경(Celery 워커가 하루 종일 여러 작업을 처리)에서도 반드시 터질 문제였으므로, 수동 브라우저 테스트가 없었다면 발견하기 어려웠을 것입니다.
