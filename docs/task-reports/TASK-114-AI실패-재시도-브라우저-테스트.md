# TASK-114. AI 서비스 실패 → 재시도/에러 처리 브라우저 수동 테스트

## 상태
보류

## 날짜
2026-11-18

## 작업 요약
사용자 승인에 따라 `GOOGLE_API_KEY`를 일시적으로 무효한 값으로 바꿔 Celery 워커를 재시작한 뒤, 새 Task를 만들어 실제 Gemini 인증 실패를 유발했습니다. 테스트 후 올바른 키로 워커를 다시 재시작해 복구했습니다.

결과: Document 탭에 `role="alert"`로 "문서 생성에 실패했습니다." + 원본 에러("API key not valid. Please pass a valid API key.")가 즉시 표시됐습니다(FR-094의 "명확한 에러 메시지" 절반은 충족). 스크린샷: `.playwright-mcp/t114-generation-failed.png`.

다만 아래 두 가지는 이번 시나리오로 검증하지 못했습니다:
1. **"재시도 중..." 안내 문구**: 유효하지 않은 API 키는 Gemini가 4xx(인증 오류)로 즉시 거부하며, T091 `GeminiClient`가 이를 재시도 불가로 분류해(T093 `GeminiAPIError.retryable=False`) 곧바로 실패 처리합니다. 즉 이 테스트 방법으로는 "재시도 중" 상태를 통과시킬 수 없었습니다. 재시도 중 상태를 보려면 429/503처럼 재시도 가능한 오류를 일으켜야 하는데, 실제 Gemini API에 그런 오류를 안정적으로 유발할 방법이 없어 보류했습니다.
2. **수동 재시도 옵션**: FR-094는 "3회 재시도 실패 후 명확한 에러 메시지와 함께 수동으로 다시 시도할 수 있는 옵션을 표시해야 한다"고 요구하지만, 실패 화면에는 에러 메시지만 있고 "다시 시도" 버튼이 없습니다. `frontend/src/components/document/DocumentViewer.tsx`를 확인한 결과 재시도 버튼 자체가 구현돼 있지 않습니다.

이 두 가지가 해소되지 않아 T114를 완료로 체크하지 않고 "보류"로 남겼습니다.
